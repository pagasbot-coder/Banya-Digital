**Участники:** PM · Senior PM · IT-архитектор · Developer · UI/UX · QA · Growth · Brand Manager · China Logistics · SME (HoReCa/FMCG) · DevOps  
**Контекст:** [`brand-pult-etapy-0-6.md`](./brand-pult-etapy-0-6.md) (док. 1, на согласовании) · Quiet Partner prod · Пульт этапов `/stages` · мост stages↔radar (ADR-006, **радар в этом треке не трогаем**)

---

## TL;DR

1. **Документ 1 — сильная база:** этапы 0–6, рубежи, 10 реестров, 9 шаблонов. Язык понятный, структура как ProjectM — Human быстро узнаёт паттерн.
2. **Главный риск:** перегруз на старте (19 артефактов). Нужен **MVP-набор** «5 реестров + 4 шаблона» и уровень **портфель → линейка**.
3. **Бизнес-вердикт:** пульт бренда — **личная мышца бренд-менеджера** (как ProjectM для РП), не waitlist-фича. Сначала dogfood на Travel+ / собес, потом продукт.
4. **Архитектура:** не новый продукт — **третий режим** в QP рядом с `/stages` и `/radar`: маршрут `/brand` (рабочее имя), тот же localStorage + MD-экспорт, **без моста в радар v1**.
5. **Внедрение в 3 волны:** (0) KB + док. 2 на примере · (A) markdown на диске / Desktop · (B) UI-клон пульта в QP · (C) опционально портфель и связка с China Logistics.

## 1) Оценка документа 1 по ролям

### Brand Manager

| Сильно | Слабо / дыра |
|--------|----------------|
| Этап 1 = ДНК до визуала — правильный порядок | Нет явного слоя **портфель** (Travel+ vs линейки vs СТМ) |
| Реестры «аудитория», «конкуренты», «платформа» закрывают 80% | Нет реестра **рисков бренда** (качество партии, greenwashing, OOS) |
| Чек полки номера — must для HoReCa | Этап 2 не ссылается на **сертификаты / состав** как рубеж |
| One-pager совпадает с playbook | «Архетип» без мини-шпаргалки (12 архетипов) — новичку тяжело |

**Предложение:** добавить в док. 1 (v1.1): реестр **Р-11 Риски бренда**; в этап 2 — пункт «состав и документы не ломают обещание»; шпаргалку «архетип за 1 мин» (опционально, 1 стр.).

### Senior PM

| Сильно | Слабо |
|--------|-------|
| Рубежи и флаги на каждом этапе | Этапы названы иначе, чем в ProjectM (Платформа vs Запуск) — **осознанно**, но нужна **таблица соответствия** |
| «Не знаем» и «Решения» — переносимо из ProjectM | Нет **вех** в привычном виде — для бренда ок, но sales любит даты в одном месте |
| Этап 0 «берём / не берём» — дисциплина | Этап 4–5 размыты без привязки к **пилоту** как вехе |

**Предложение:** таблица «этап пульта бренда ↔ этап ProjectM» в приложении; в реестр «Запуск» жёстко вшить вехи: образец → пилот → повторный заказ.

### PM

Док. 1 готов к **dogfood** после согласования Human и **док. 2** (заполненный пример). Не начинать код до: (1) ОК док. 1, (2) один прогон Human по Travel+ Natural в markdown, (3) Go на волну B.

Очередь QP: отдельный эпик **T-Brand-001…** (не смешивать с T-103 мост stages↔radar).

### SME (HoReCa / amenities)

| Плюс | Минус |
|------|-------|
| Двойная аудитория: гость + закупщик | Мало про **дистрибьютора** (NS в каталоге ≠ свой бренд) |
| Возражения sales — на месте | Нет блока **СТМ отеля** (логотип сети на вашей формуле) |

**Предложение:** в ш-03 и реестр аудитории — строка «тип сделки: каталог / тендер / СТМ».

### China Logistics

Этап 2 и 4 **молчат** о поставке. Для физ.товара обещание бренда = качество партии + срок.

**Предложение:** не отдельный этап — **обязательный чек** в этапе 2 и 4: «COGS/поставщик/срок согласованы с логистикой»; ссылка на `china-russia-logistics.md`; при риске — строка в Р-11.

### Growth

Пульт бренда **не для лендинга**. Waitlist и GTM QP не трогаем. Ценность — Human использует на собесе и в пилоте Travel+ → кейс для контента позже.

**Не делать:** третья большая кнопка на hub без dogfood.

### UI/UX

Паттерн ProjectM проверен: этап слева → реестр → экспорт MD. Для `/brand` — **тот же shell**, другие колонки и цвет акцента (отличить от `/stages`).

Риск: 10 вкладок реестров — перегруз. **MVP UI:** 5 вкладок + «ещё» свёрнуто.

### Developer

Док. 1 — спецификация контента. Реализация = **форк** `lib/stages/` → `lib/brand/`, `components/stages/` → `components/brand/`, `content/projectm/` → `content/brand/`.

Переиспользуем: `registers.ts` схема, `objectsToMarkdown`, localStorage persist, `StagesShell` layout. Новое: колонки реестров, этапы gate-тексты, demo «Travel+ Natural».

Оценка волны B: **~1 эпик (T-Brand-001…008)**, без БД, без auth.

### IT-архитектор

| Принцип | Решение |
|---------|---------|
| Канон | Операционка бренда = пульт `/brand`; рефлексия PM = `/radar` (**мост не в v1**) |
| Persist | `qp-brand-{projectKey}-*` localStorage, как `qp-stages-*` |
| Контракт | `brandPultSnapshot v1` — только для экспорта/бэкапа, не для radar |
| Не делать | Склейка brand+stages+radar в один экран; server sync; обязательный FS Access на Vercel |

### QA

Критерии приёмки волны B: этап 0→1 рубеж блокирует переход; реестр сохраняется после refresh; MD-экспорт UTF-8; demo-тест заполняет все MVP-реестры; disclaimer «не юр./мед. совет» если есть состав.

### DevOps

Только Vercel static route. Секретов нет. PostHog — те же события `brand_register_edit`, `brand_stage_change` (без PII названия линейки в аналитике — только `stage_id`).

### Копирайтер (шеф-редактор)

Тон док. 1 — ровный, без воды. Доработать: единый глоссарий в шапке (линейка / SKU / обещание / СТМ); в шаблонах — **подсказки в скобках** (как в ProjectM).

## 4) Архитектура внедрения в Quiet Partner

### 4.1 Место в продукте

```text
quiet-partner/
├── /stages      ← Пульт этапов (PM, 0–6)           [есть]
├── /radar       ← Тихий напарник (8 доменов)       [есть]
├── /brand       ← Пульт бренда (линейка, 0–6)      [предлагаем]
└── / (hub)      ← выбор режима (после dogfood B)   [опционально]
```

**Радар не трогаем** в этом эпике. Мост stages↔radar (T-103…) — отдельный трек.

### 4.2 Структура кода (волна B)

```text
content/brand/
  01-etapy-linii.md          # шпаргалка этапов (из док. 1)
  02-dnk-one-pager.md
  03-sobes-brend.md

lib/brand/
  registers.ts               # STAGES + REGISTERS (колонки из док. 1)
  demoNatural.ts             # демо Travel+ Natural (после док. 2)
  export.ts                  # MD export (reuse stages utils)

components/brand/
  BrandPageClient.tsx
  BrandShell.tsx             # клон StagesShell, другой nav

app/brand/
  page.tsx
```

**localStorage:** `qp-brand-{projectKey}-cache`, `qp-brand-meta` (имя линейки, stageId).

### 4.3 Контракт снимка (только бэкап / перенос)

```text
brandPultSnapshot v1
────────────────────
schemaVersion: 1
projectKey: string
lineName: string
stageId: 0..6
registers: Record<registerId, rows[]>
updatedAt: ISO
source: "brand-pult"
```

Импорт в QP — кнопка «Восстановить из файла». **Не** писать в radar store в v1.

### 4.4 Что переиспользовать из `/stages` (DRY)

| Модуль stages | brand |
|---------------|-------|
| `objectsToMarkdown` | да |
| `emptyRow`, table editors | да |
| `StagesShell` layout | форк → `BrandShell` |
| `demoTestRun` | `demoNatural` из док. 2 |
| `bridge.ts` | **нет** в v1 |
